# Clean Architecture violations in core-mapping, 2026-09-28

The layer structure of `core-mapping` holds: no import goes from domain to an outer layer, from application to
infrastructure, presentation or controllers, nor from controllers to domain. The meaning of Clean Architecture does
not: the domain model is the save file format, the value objects are view projections, and the infrastructure takes
business decisions.

Perimeter: every file of `packages/core-mapping/src`, the entry files of `cli-merge`, `cli-validate` and
`ui-save-manager`, `packages/shared-save-processing`, the live decisions of the corpus and the architecture rules of
the instructions corpus, read on 2026-09-28 at commit c23522e. Import facts were measured with `grep -rn "from" packages/core-mapping/src/<layer>`.

| Measure                                                                  | Value    |
|--------------------------------------------------------------------------|----------|
| Presenter ports taking a domain type                                     | 5 of 9   |
| Presentation files importing `domain/`                                   | 6        |
| Value object files, none with a method beyond its factory                | 13       |
| Domain files using a wire abbreviation (`gId`, `liId`, `woIds`, `siIds`) | 5        |
| Domain files importing runtime code of `shared-save-processing`          | 3        |
| Application files importing runtime code of `shared-save-processing`     | 2        |

Grades follow the architecture review scale: critical, a dependency-rule or direct boundary violation; high, a
responsibility violation creating strong coupling or leaking technical concerns inward; medium, a design smell
making future violations likely; low, a naming, organization or clarity issue without current violation.

Two live decisions of the corpus entrenched violations 1 and 8 against the architecture rules of the instructions
corpus: `APresenterReceivesAValueObjectNeverAnEntity` and `APlanetEnergyGridIsAnAggregate` (its rejection of
"assembling the value object in presentation: the PresenterPort would stop receiving a domain value"). Both are
replaced when the violations they justify are corrected.
